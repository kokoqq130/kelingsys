# 柯灵资料整理与本地查询

这是一个**本地私密医疗资料整理项目**，当前不以产品化、公开部署或多人在线录入为目标。

核心使用方式只有三步：

1. 家属通过文字、图片、PDF或报告文件补充信息。
2. AI读取原始资料，完成OCR、数据解析、住院整理和长期主文档更新。
3. 本地启动查询页面，查看总览、时间线、当前用药、住院记录、检查结果和原始资料。

## 隐私警告

`柯灵用/` 中包含真实医疗隐私资料。仓库和任何备份必须保持私有，不得把该目录、索引JSON、PDF或原始报告部署到公开网站。

当前不维护自动公开部署。静态导出默认被安全开关阻止；日常查看请直接启动本地前后端。

## 哪些内容是事实来源

按优先级理解：

1. 原始报告图片、医院PDF、出院记录、处方等原始证据。
2. 每次住院目录中的住院整理Markdown，记录当次事件。
3. `柯灵用/柯灵基本信息.md`，保存当前状态、当前用药和长期时间线。
4. SQLite索引、网页、PDF、静态JSON和构建目录都是派生产物，可以重新生成，不能反向修改事实来源。

### 当前用药的唯一权威入口

当前用药只以 `柯灵用/柯灵基本信息.md` 中的“目前治疗方案”为准，并必须写明截至日期。

住院文档中的药物内容只表示当次发生过的调药，不能直接解释为现在仍在使用。

## 日常资料整理流程

1. 将新文件放入对应住院或检查目录。
2. 使用项目本地 `medical-report-organizer` skill 做OCR和整理。
3. 先保留原始资料，再生成或更新住院整理Markdown。
4. 把长期有价值的信息同步到主文档；短期化验细节留在住院文档。
5. 新旧信息不一致时保留旧时间轴，在新日期追加变化；无法确认时标记“待核对”。
6. 运行一致性检查：

```powershell
.\scripts\Check-ProjectConsistency.ps1
```

7. 启动本地页面查看结果。

## 启动本地查询页面

一键启动：

```powershell
.\scripts\Start-QueryApp.ps1
```

也可以分别启动：

```powershell
.\scripts\Start-Backend.ps1
.\scripts\Start-Frontend.ps1
```

默认地址：

- 前端：`http://127.0.0.1:5173`
- 后端：`http://127.0.0.1:8000`

后端启动时会自动重建索引，因此Markdown更新后重新启动即可看到最新内容。也可以调用本地 `/api/reindex` 重新索引。

## 将资料移到仓库外

长期维护时，推荐把真实医疗资料移到独立私密目录。后端支持：

```powershell
$env:KELING_DATA_ROOT = 'D:\kelingsys-private'
.\scripts\Start-QueryApp.ps1
```

索引路径也可以调整：

```powershell
$env:KELING_INDEX_DB_PATH = 'D:\kelingsys-runtime\index.db'
```

目前不要求立即移动，先保持现有链接稳定即可。

## 为什么长期维护不会直接覆盖冲突

项目采用“原始证据—当次事件—当前摘要—派生展示”四层结构：

- 旧住院经过不会因为后来调药而被改成新剂量。
- 新剂量进入主文档当前治疗方案，同时在时间轴保留调药日期。
- 查询系统展示时优先读取主文档的当前方案，并把住院调药作为历史事件。
- 不确定信息不自动选择答案，而是保留来源并标记待核对。

只要遵守这四层边界，并在每次更新后运行一致性检查，长期维护中的冲突可以被发现和保留，而不是静默覆盖。

## PDF与静态导出

- 修改主文档后不会自动覆盖PDF，必须由用户明确确认。
- 如果Markdown比PDF新，一致性检查会给出“PDF已过期”警告。
- 静态导出包含敏感内容，默认禁止；日常本地展示不需要静态导出。
